# PlayerStats

Класс: `PlayerStats` (`extends Resource`, `class_name PlayerStats`).

Файл базы: `res://data/player_stats_default.tres`. В нём стартовые параметры и `essence = 0`. Это шаблон, сессия в него не пишет.

Экран подготовки делает `duplicate(true)` и ставит `essence = PrepRules.START_ESSENCE` (`100`). Траты идут по этой копии. Сервер перед матчем собирает вторую копию с тем же бюджетом и теми же рангами. В узел игрока попадает только серверная копия. Подробности экрана — в [prep.md](prep.md).

`current_stamina` и `current_hp` в ресурс не входят. Это поля узла `Player`. При спавне сервер ставит их равными `max_stamina` и `max_hp`.

## Поля

| Поле | Тип | База | Шаг | Базовая цена | Рост цены | Потолок |
|---|---|---|---|---|---|---|
| `essence` | `int` | `0` в `.tres`, `100` на подготовке | — | — | — | нет |
| `max_hp` | `float` | `100.0` | `+25` | `12` | `+5` за ранг | `200.0` |
| `move_speed` | `float` | `180.0` | `+15` | `10` | `+5` | `330.0` |
| `max_stamina` | `float` | `100.0` | `+20` | `10` | `+5` | `200.0` |
| `dash_multiplier` | `float` | `1.8` | `+0.15` | `15` | `+5` | `2.55` |
| `vision_zoom` | `float` | `1.0` | `+0.1` | `12` | `+5` | `1.5` |

`essence` на подготовке — общий кошелёк. Им же оплачивается крафт слотов. В матче поле больше не уменьшается: остаток просто приезжает на игрока вместе со сборкой.

Служебные ранги, старт `0`: `hp_rank`, `move_speed_rank`, `max_stamina_rank`, `dash_rank`, `vision_rank`. Цена следующего ранга: `base_cost + rank * cost_growth`. После покупки ранг увеличивается на 1.

`vision_zoom` — насколько камера отъехала. `1.0` — базовый кадр. Выше значение — шире обзор. Перевод в `Camera2D.zoom` описан в [player.md](player.md).

`max_hp` — потолок здоровья. Урон в матче снимает `current_hp` на узле игрока, потолок за бой не покупается.

Шаги сходятся с потолком без остатка:

- здоровье: 4 покупки, `100 → 200`;
- скорость: 10 покупок, `180 → 330`;
- стамина: 5 покупок, `100 → 200`;
- рывок: 5 покупок, `1.8 → 2.55`;
- обзор: 5 покупок, `1.0 → 1.5`.

Сумма всех потолков больше `100`, поэтому за одну подготовку снимается часть веток. Это заложено в бюджет.

## Списание

```gdscript
func try_spend(cost: int) -> bool:
    if cost < 0 or essence < cost:
        return false
    essence -= cost
    return true
```

Неуспешный вызов оставляет `essence` как было. Ниже нуля поле не уходит.

У каждого параметра свой метод. Порядок внутри один:

1. Параметр уже на потолке — вернуть `false`. Цена не списывается.
2. `try_spend` текущей цены. Не хватило — `false`, параметр не меняется.
3. Прибавить шаг, зажать потолком, увеличить ранг.
4. `emit_changed()` и вернуть `true`.

```gdscript
func try_upgrade_max_hp() -> bool
func try_upgrade_move_speed() -> bool
func try_upgrade_max_stamina() -> bool
func try_upgrade_dash_multiplier() -> bool
func try_upgrade_vision_zoom() -> bool
```

Методы сеть не проверяют. Их вызывает черновик подготовки и повтор того же числа рангов на сервере. Готовые числа здоровья и скорости клиент на сервер не присылает: сервер доверяет только счётчикам рангов и сам вызывает эти методы. См. [prep.md](prep.md).
